# BPD-TRM-CURATE-03A: exact optimizer-aware screening primitive

Based on frozen development PR #170 head af43e48b1ed472eef88bedd0cfa8f4f8aefb49b5. The prior eight-root campaign, failed behavioral admission and source freeze remain untouched. This is an engineering primitive plus proposed next protocol, not a new native TRM training campaign.

For a candidate gradient g from the parent checkpoint, globally clip by c=min(1,clip/(||g||+1e-6)). For each parameter group, update m'=beta1*m+(1-beta1)*c*g, v'=beta2*v+(1-beta2)*(c*g)^2, with the maximize flag applied to the clipped gradient, bias correction at t+1, AMSGrad max when applicable. The displacement is the actual rounded candidate parameter minus the parent, using decoupled weight decay and corrected moments. Predicted calibration gain is -<g_cal,delta>. This accounts for preexisting moments, weight decay, candidate-dependent denominators, missing gradients, and clipping. A frozen diagonal preconditioner alone does not in general reproduce the AdamW displacement. The calibration linearization is an approximation to nonlinear loss gain. If the calibration gradient is L-Lipschitz on the entire update segment, the Taylor error is bounded by L||delta||^2/2. No certified L was obtained here.

The read-only helper receives precomputed gradients in optimizer parameter order. Caller must isolate forward/backward native state, buffers and RNG. A detached gradient computation alone is not a proof of rollback of callback effects. Final selected four-edge batch must use a separate whole-transaction acceptance test and either commit all state or restore all state, not only model and optimizer dictionaries. The existing campaign's final rejected-window path restores only those dictionaries; the candidate probe transaction has stronger custody. Do not mix candidate counterfactual labels with actual committed batch improvement.
