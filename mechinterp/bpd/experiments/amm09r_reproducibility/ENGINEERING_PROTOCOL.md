# AMM-09R CPU reproducibility engineering registration

Registered 2026-11-18 before executing this harness. This work addresses
[issue #111](https://github.com/MoralityLabAI/BPD/issues/111). It is excluded
engineering. Its observations cannot be counted as fresh scientific evidence.

## Frozen scope and order

1. Preserve AMM09 source and every historical result byte. Historical diagnostic
   runs may access only the 64 already exposed AMM09 training roots. Repeat the
   original training program twice in separate processes per worker and compare
   every recorded root weight hash, candidate bit, and policy to the original
   archived training receipt. Historical development and confirmation are never
   generated by this harness.
2. Compare two registered configurations on eight new excluded roots. Seed text
   is `AMM09R-ENGINEERING-V1/` followed by the original root/stream arguments.
   The model-root phase is always `engineering`, indices 0 through 7, with both
   original families represented. All candidates use identical root streams.
3. Run both configurations twice in separate processes on each of two separate
   GitHub-hosted workers. Worker labels are ubuntu-22.04 and ubuntu-24.04. Record
   actual CPU model and capability; different labels do not prove different
   processors. If observed CPUs are identical, report that narrower scope.
4. Select controlled float32 only by the exact equality and physical criteria
   below. No success-rate criterion chooses the numerical configuration. A
   failure requires a new committed engineering amendment before testing a
   fallback. Float64, rounding changes, altered losses, and new thresholds are
   outside this registration.
5. Only after engineering acceptance may a separate AMM09R scientific protocol
   register fresh training and development namespaces. All AMM03-09 and ARG-03-N
   protected populations remain sealed. This file grants no confirmation access.

## Recorded endpoints and decision rule

For each root, retain dtype/shape-tagged canonical tensor hashes plus numeric
arrays for initial physical and factor parameters, final physical parameters,
canonical factors, effective operators, and rank-one component products. Hash
all source minibatches before optimization. Retain six-mask features, future
probes, normalized patches, and signed margins `.18 - max(abs(probe-target))`
for the 128-pair training fixture and 512-pair independent engineering assay.
Record the unchanged candidate success bits. Instrumentation captures the
factor product immediately before SVD without altering its inputs or outputs.

Fit one engineering-only global ridge fixture across the eight roots' 128
pairs using the original lambda 10 and four-decimal coefficient rounding.
Store raw and rounded coefficients, pooled action, and frozen-prior decisions
on the independent 512-pair assay. Its scores are engineering diagnostics.

The primary gate requires bit-exact equality of the deterministic payload
within and across workers for pinned32: initialization and inputs, trained
parameters, canonical factors/products, features/probes/patches/margins,
candidate labels, and ridge/policy output. Signed zero bytes are included in
tensor hashes. Worker identity, timestamps, process IDs, timings and provenance
are excluded from that payload. Hash mismatch fails the candidate even when
success counts agree. Baseline failures remain archived and described.

No mismatch is downgraded to a passing warning. Report changed bits with both
signed margins, maximum absolute numeric deviations, and first differing
recorded stage. SVD sign flips are separately identifiable through rank-one
products, but still fail the registered raw-factor equality criterion.

## Physical admission and source safeguards

All eight roots must pass six-mask admission, finite values, equal active L2
dose within 1e-5, and exactly zero immediate readout displacement. The complete
operator must survive the registered GL(3) shear within 1e-9. For roots with
singular gap above .01, recanonicalized rank-one products must agree within
1e-8. Low-gap roots stay in every numerical comparison and are reported.

Check actual BPDModel and PassMaskSchedule execution for each permitted subset,
the projected/rescaled donor write, both delayed readouts, and pass-counter reset
with parity tolerance 1e-5. Keep the original float32 native wrapper unchanged.
The full donor state has the same L2 displacement D and can alter the current
readout. It is an unrestricted visible donor-state control. Its successes need
not dominate the six-mask oracle, and it is never available to the policy.

An immutable historical source/receipt audit remains distinct from engineering
acceptance. A new pinned32 match across current workers does not establish
historical AMM09 source reproduction unless original training hashes match.
No scientific p-values, causal effect claims, or confirmation release follow
from the engineering policy fixture. Pinned EvalMath is required for any
subsequent scientific development study.

### Physical-check detail frozen with the first source commit

The first source commit also checks the fixed diagonal GL(3) rescale
diag(2, .5, 1) and the signed permutation [[0,0,-1],[1,0,0],[0,1,0]].
The same 1e-9 full-operator and conditional 1e-8 canonical-component bounds
apply to these transforms. This detail is recorded before the first harness
execution. No model outputs informed it.
