## Native BPD execution

[`native_adapter.py`](native_adapter.py) replaces the historical recurrent
factor operation with the repository's `TiedComponentLinear`. It copies
`V_native = V_source` and `U_native = U_source.T`, keeping the source factors as
the actual trainable path. Default component gates are open. An explicit zero
residual gate prevents the frozen target-weight residual from cancelling factor
updates. The encoder, context term and action head remain ordinary trainable
layers.

The adapter supports the historical `mid` / `finish` helpers. Each replayed
finish resets the local mask index and restores its global pass index. Explicit
continuation objects keep the intended schedule when histories are interleaved.
Legacy `finish` raises if it receives a stale boundary.

Run this import pattern from the repository root:

```python
from mechinterp.bpd.experiments.hadamard_population.had05 import Recurrent
from mechinterp.bpd.experiments.hadamard_population.native_adapter import (
    native_from_recurrent,
)

native = native_from_recurrent(Recurrent())
logits = native(history)  # float32 [batch, population, history, 15]
boundary = native.boundary(history, pass_offset=5)
edited_logits = native.resume(boundary, boundary.hidden + edit)
```

The 29 native tests cover forward and gradient parity within declared numeric
tolerances, component-mask gradients, interleaved continuations, repeated
counterfactual finishes, the four historical update-helper arms, and disk
checkpoint round trips. One bounded allocator fixture agrees exactly on every
returned field except elapsed time after conversion. The tests ran through the
real package initializer and its transitive imports. Optimizer parity holds the
shared action-logit bias fixed, since its exact loss gradient is zero. A first
remote run exposed AdamW's amplification of float32 residue in that coordinate.
The failure and the revised test contract are preserved in
[CI_NUMERICS.md](revision_20261126/CI_NUMERICS.md). Ordinary forward and
all-parameter gradient tolerances stay unchanged.

The tested scope is native component execution of the existing recurrence.
The adapter retains the four-observation replay used by HAD-05. Persistent
policy training and native TRM attention remain future work.
The factored recurrent write and the context term provide distinct routes for
state information, which matters when interpreting an ablation.

## Corrected search boundary

The archive runners could miss an already completed initial trajectory after
spending their remaining budget on archive observations. Zero-round runs also
skipped that check. The concrete seed-3, length-3 fixture already contains a
valid order-12 construction. Historical `archive16` could return `best: 0`
with `solved: false` after charging 10 of 12 candidate units.

`archive.py` and `near.py` now scan the whole starting population before archive
work. They also check for a completed state before a loop budget exit. A solved
start returns its certificate with zero charged work. The regression suite
exercises all eight archive arms, including a solution in a later population
slot. [BUDGET_EDGE_PATCH.md](BUDGET_EDGE_PATCH.md) records the original source
blob identifiers. The replay receipts in this revision used those frozen
historical versions, preserving their original experimental meaning.

## Reproduce the checks

From the repository root, with Python 3.12, NumPy 2.3.5, Torch 2.15.0+cpu and
pytest 9.2.0:

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTHONPATH=. OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
python -m pytest -q \
  mechinterp/bpd/experiments/hadamard_population/test_native_adapter.py \
  mechinterp/bpd/experiments/hadamard_population/test_math_bounds.py \
  mechinterp/bpd/experiments/hadamard_population/test_budget_edges.py \
  mechinterp/bpd/experiments/hadamard_population/test_receipt_checks.py

python mechinterp/bpd/experiments/hadamard_population/verify_replay.py
```

Local result: **79 tests passed, 8 subtests passed**. The compressed-receipt
audit also passed. A focused GitHub Actions workflow runs these checks and
uploads its receipts. Its status is visible on the pull request.

To repeat the exposed development study, export the five sources from the
pinned original commit into a separate directory. Then call `replay_frozen.py`
with `--source-dir` pointing to that directory and `--out-dir` pointing to a
fresh output directory. The runner refuses altered source and preserves
runtime, commands, logs, failures and hashes. Its original replay used NumPy
2.3.5 and Torch 2.15.0+cpu; the historical report used Torch 2.10.0+cpu.
