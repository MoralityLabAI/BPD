## Trainer integration
New explicit BPDTrainer constructor arguments cache_single_backward_residuals=False and residual_cache_max_bytes=16*1024**2. Existing defaults and config schema unchanged. With the flag true, independent ResidualVJP contexts surround only stochastic mask and clean-window adversarial rollouts. These contribute once to the final joint backward. Clean capture/mean calibration, faithfulness warmup/loss, evaluation, closed-loop inner PGD and final PGD loss with retain_graph=True remain reference. Stats per step record actual hits, backward nodes, reconstruction and cap bypass; scope exits before backward. The frozen independent-residual implementation assumes CPU float32 contiguous fixed parameters, sequential non-checkpointed first-order graph, no external storage mutations, no concurrent/reentrant calls. Unsupported configurations fall back where the kernel implements fallback. Higher-order differentiation/checkpoint/reentrant/concurrent use remain outside contract; the opt-in caller is responsible. No GPU enablement, production default or checkpoint change.

The complete native harness imports BPDModel, BPDTrainer, TRMBPDAdapter, CI, losses and PGD and compares reference/cache on 64/128 widths, closed_loop/clean_window, six passes, 4 paired steps per setting, one faithfulness warmup, 2 inner PGD steps, stochastic/adversarial branches, actual optimizer/CI/PGD states, RNG, deterministic evaluation and greedy readouts. It asserts scope counts (one closed-loop, two clean-window), numeric cache and restoration behavior. Full package unavailable in local container; GitHub DNS failed and raw retrieval unavailable. This harness is committed, source reviewed, but NOT executed. No claim of end-to-end trainer parity or speed. Native command:
